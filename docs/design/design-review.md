# 设计稿评审最终报告与执行计划

## Context

Claude Design 交付 8 个画板（目录名 `Nocturne vs. brief conflict`）。经我方分析 + Codex 独立复核，**视觉方向合格，但不能按原样进入实现**：存在两处可量化的可访问性缺陷、一处会导致现有暗色全失效的迁移陷阱、以及 2/3 的功能未覆盖。

本报告= 双方结论对齐后的定案。**Codex 推翻了我 3 个判断、补充了 2 个 P0 级遗漏**，均已并入。

---

## 一、结论对齐

| # | 议题 | 我方判断 | Codex 复核 | **最终定论** |
|---|---|---|---|---|
| 1 | 两套设计系统冲突 | 属实，建议删 `_ds/` | 事实属实；**"删整个目录"过激** | ✅ 事实成立；处置改为**先提取规范再删生成物** |
| 2 | 响应式中间档坏 | P0 阻塞 | 同意，证据充分 | ✅ **P0** |

### Codex 补充的两个 P0（我方完全遗漏）

| 议题 | 证据 | 严重度 |
|---|---|---|
| **可访问性** | 亮色弱文本 `#8c90a3`/`#f5f6fa` = **2.93:1**；暗色 `#6f7386`/`#131520` = **3.87:1**（标准 4.5:1）· 开关是 `label+span+onClick`，**键盘不可操作** · 模态框无 `role="dialog"`/焦点陷阱/Escape · 8 画板**零 `aria-*`** · 无 `prefers-reduced-motion` | **P0** |
| **主题迁移兼容** | 现工程 `html.dark` + `darkMode:'class'`（`main.ts:26-34`、`tailwind.config.js:4`），已有大量 `dark:*` 类。改用 `[data-theme]` 而不并行维护 `html.dark` → **现有页面暗色全失效** | **P0** |

## 二、修订后的问题清单

### P0 — 不冻结就会持续返工

| # | 问题 | 处理 |
|---|---|---|
| 1 | **响应式中间档** | 补 1024 / 1280 / 1440 断点；定义表格列优先级与顶栏降级顺序；Key 列 `nowrap` |
| 2 | **可访问性基线** | 弱文本色提到 ≥4.5:1；开关改 `role="switch"`+`aria-checked`+键盘；模态补 `role="dialog"`/焦点陷阱/Escape；补 `prefers-reduced-motion` |
| 3 | **危险操作确认缺失** | 删除/停用/重置配额/**重置速率窗口用量**（`KeysView.vue:1824-1857`，我方原清单遗漏此项）四类均需确认稿 |
| 4 | **仪表盘信息架构** | 唯一化：Dashboard = 用户侧摘要；`/monitor` = 渠道维度详情。删除 Console 画板主区 |
| 5 | **主题迁移策略** | 先建语义 token 兼容层，`html.dark` 与 `[data-theme]` **并行维护**，逐页迁移后再摘除 |
| 6 | **暗色 accent ramp** | 补 `--color-accent-100…900` 九档 |
| 7 | **品牌/配置契约** | 区分品牌文案（可换）与协议标识（`AIPROXY_API_KEY`、`sk-ap-` 前缀、provider 名——**须先确认 CLI/SDK/后端校验契约**，不能只做字符串替换） |

### P1 — 影响一致性与迁移成本

| # | 问题 | 处理 |
|---|---|---|
| 8 | **平台色 token**（升级自 P2） | 定义 5 家色值（含 Antigravity）；**解耦 Grok `#8c90a3` 与 `--color-text-3` 的角色冲突** |
| 9 | **币种语义** | 不可机械统一为 `$`。真实支付支持动态币种（`types/payment.ts:45`），Key 配额以 USD 展示。需分层定义：**账户展示币种 / 支付币种 / 计费基准币种** |
| 10 | **Keys 数据模型** | 画板把 `quota: .31/.97` 当比例直接画百分比；真实模型是 `quota_used / quota`（`KeysView.vue:214-225`），设计样例**掩盖了"实际已用金额"字段缺失** |
| 11 | **时间格式** | 画板混用完整日期 / `14:02:31` / `昨天 22:10` / `08-30 09:12` 四种，未定义时区、年份省略、相对时间规则 |
| 12 | **8 页未画 + 2 公开页** | 补画 4 张高价值页；其余工程侧实现 |
| 13 | **`aiproxy-theme.css` 三处缺陷** | ① 根选择器 `.ap, [data-theme="light"]` 但暗色仅 `[data-theme="dark"]`，脱离 `.ap` 的暗色节点拿不到字体/圆角/时长 ② Google Fonts 运行时远程 `@import`（CSP/离线/国内网络会失败）应自托管 ③ `.ap button, input, select` **漏了 `textarea`** |

### P2 — 纯视觉一致性

| # | 问题 |
|---|---|
| 14 | Token 趋势两套（Dashboard 5 线含双 Y 轴不可判读 ↔ Usage 3 线）→ 统一，命中率单独成图 |
| 15 | 图表挪用语义色（warning/success 当分类色）→ 定义独立图表色板 |
| 16 | 代码块硬编码 `#131520`，亮色下是突兀黑框 → 改 token |
| 17 | Subscriptions 用套餐名、Keys 用分组名，实体口径不一 |
| 18 | 订阅胶囊按 token 计 ↔ 订阅卡按金额计 |
| 19 | 两份 shell 已漂移（`Console.dc.html` 手写副本 ≠ `console-shell.js`）→ 以后者为准 |
| 20 | 组件表漏收 12 类已在用组件（骨架屏/空态/Tooltip/下拉/日期区间/图表容器/代码块/可复制 chip/竖排操作组/顶栏胶囊/开关折叠组/确认弹窗） |

| 副标题 / 版权 / 客服邮箱 | 3 | `site_subtitle` / 当前年 / `contact_info` | 无 |

| **环境变量名 / provider 标识 / Key 前缀** | 20+ | — | ⚠️ **须先确认 CLI、SDK、后端校验契约**，不能只做字符串替换 |

## 四、执行计划（端到端样板优先）

> Codex 否定了原「设计返工 → 设计补全 → 工程落地」的串行安排：会导致阶段 B 全部画完后被 C 推翻。改为样板先行。

```
阶段 0 样板（串行，必须先完成）
  token 冻结 · 主题兼容策略 · Shell · 响应式矩阵 · 无障碍基线
  用 Dashboard + Keys 两页跑通设计→代码闭环
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
  阶段 A 设计补全           阶段 B 工程铺开
  （并行，4 张高价值页）     （并行，组件库 + 已有画板页）
        └───────────┬───────────┘
                    ▼
              阶段 C 收尾
        无画板的 8 页 + P2 一致性项
```

### 阶段 0：端到端样板（阻塞项，全部在此冻结）

| 任务 | 产出 | 判据 |
|---|---|---|
| 0-1 冻结设计 token | 色板（含平台色 5 家 + 图表色板 + 暗色 accent 九档）、间距规范化、圆角、字体 | Design System 画板可查到全部值 |
| 0-2 主题兼容策略 | `html.dark` 与 `[data-theme]` 并行方案 + 迁移顺序 | 现有页面暗色不失效 |
| 0-3 响应式矩阵 | 1024/1280/1440 三档 × 表格列优先级 × 顶栏降级顺序 | 内容区 660px 无竖排/折行/重叠 |
| 0-4 无障碍基线 | 对比度达标色值、开关/模态语义规范、焦点管理、`prefers-reduced-motion` | 对比度实测 ≥4.5:1；键盘可完成全流程 |
| 0-5 Shell 实现 | `AppSidebar` / `AppHeader`（尺寸抄 `console-shell.js`：260/72px、56px、34px） | 三态切换正常 |
| 0-6 两页闭环 | Dashboard + Keys 从设计到 Vue 代码跑通，含 Keys 四类危险确认 | 真机验证通过 |

### 阶段 A：设计补全（与 B 并行）

| 优先级 | 页面 | 理由 |
|---|---|---|

| 2 | 模型广场 | 对外报价，双层表头宽表是难点 |
| 3 | 个人资料 | 11 个子组件，含 TOTP 向导与 Passkey |
| 4 | 渠道状态 | 承接仪表盘让出的渠道维度指标 |

### 阶段 B：工程铺开（与 A 并行）

| 批次 | 内容 |
|---|---|
| B1 | 主题层：抽 `aiproxy-theme.css` 变量到 `src/styles/theme.css`，修复三处缺陷（作用域、字体自托管、补 `textarea`） |

| B4 | 已有画板的页面：Usage / Subscriptions |

### 阶段 C：收尾

无画板的 8 页（可用渠道、批量图片、我的订单、兑换码、推广返利、密钥查询、法律页、404）+ P2 一致性项。

### 明确不做

- ❌ 引入 `_ds/nocturne-*/styles.css`（紫色单暗色，污染 `body`/`h1-h6`/`a`）——但**先提取 readme 中的焦点规范、状态设计、组件清单**再删生成物
- ❌ 引入 `support.js`（69KB Claude Design 画布运行时，依赖 `window.React`）
- ❌ 原样引入 `aiproxy-theme.css`（`.btn-p`/`.row-hover` 用 `!important`，与 Tailwind 冲突）
- ❌ 把 Console 版运维指标搬到渠道状态页（/monitor V2 已有，会双重定义）
