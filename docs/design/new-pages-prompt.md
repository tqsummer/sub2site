## 0.1 复用已冻结的规范，不要另起炉灶

- 色板 / 圆角 / 字体 / 动效时长：全部取自 aiproxy-theme.css，不要引入新色值。
- Shell：所有需要登录的页面都套 window.ConsoleShell，不要手写侧栏和顶栏。
- 组件：优先复用 AIProxy Components.dc.html 里已定义的 12 类组件（骨架屏、空态、
  Tooltip、下拉、日期区间、图表容器、代码块、可复制 chip、竖排操作组、顶栏胶囊、
  开关折叠组、确认弹窗）。确实需要新组件时，画完后补进 Components 画板。

唯一一处要改的色值：--color-danger 亮色 #dc2626 → #d92020

原因：#dc2626 在页面底色 #f5f6fa 上对比度是 4.47:1，差 0.03 没到 4.5。#d92020 是 4.65:1。
（在卡片底色 #fdfdff 上原值 4.75:1 是合格的，所以只在页面底色上有问题，但仍需修。）

## 0.2 断点

断点按内容区宽度判断，不是视口宽度。页面里要取当前档位，一律调用 window.apLayout()，
不要自己读 window.innerWidth。

每页都要出 1024 / 1280 / 1440 三档截图。侧栏展开/折叠不影响档位（这是上一轮修好的行为，
保持不变）。

移动端（视口 < 1024）为抽屉态。本轮四页都要给移动端布局，因为其中三页是表格重灾区。

## 0.3 无障碍

沿用上一轮的基线，不再重复解释：

- 所有文本对比度 ≥ 4.5:1
- 开关用 role="switch" + aria-checked + 键盘可操作
- 对话框 role="dialog" + aria-modal="true" + aria-labelledby + data-dialog + 焦点陷阱 + Escape
- 危险操作用 role="alertdialog"
- 可排序表头带 aria-sort
- 下拉选择器用 role="listbox" / role="option"，触发按钮 aria-haspopup="listbox"
- 菜单用 role="menu" / role="menuitem"，触发按钮 aria-haspopup="menu"
- 进度条用 role="progressbar" + aria-valuenow/min/max
- 装饰性图形一律 aria-hidden="true"

## 0.4 间距

4px 网格。1px / 2px 只用于描边和发丝线，不作为间距。

## 0.5 品牌与配置动态化

以下内容都来自后台配置，不能硬编码：

  站点名           siteName        传给 ConsoleShell；模型广场独立形态的导航条也要用
  Logo             logoUrl         用 window.BrandLogo，缺图降级为首字母块
  API 域名         api_base_url    出现在文档链接、示例代码里
  客服联系方式      contact_info    个人资料页的联系客服卡

## 0.6 时间与币种

时间：一律 UTC+8，页面底部加「时间为 UTC+8」底注（与 API 密钥页一致）。

币种：分三层，不能统一写成 $
  - 账户余额：始终 USD
  - 支付币种：动态，11 种之一 —— CNY / HKD / USD / EUR / GBP / AUD / CAD / SGD / JPY / KRW / NZD
  - 套餐价格：跟随套餐自身的 plan.currency

## 0.7 图表配色

用已冻结的独立图表色板，不要挪用语义色（warning / success / danger 只表示状态，
不当分类色用）。唯一例外是渠道状态页的健康色阶——那里颜色本身就是语义（见 4.5）。

## 1.1 定位

窄栏表单型页面，是整个产品的转化关键路径。这是四页里最重要的一页。

- 路由：/payment
- 容器：居中窄栏（现有实现是 950–1024px 级别的最大宽度），不是全宽表格页
- 侧栏高亮：充值 / 订阅

## 1.2 两个 Tab × 两个相位

页面有两个正交的维度，必须都画出来：

Tab（activeTab）：recharge 充值 ｜ subscription 订阅
  - 只有一个 tab 可用时，整个 tab 切换器隐藏（不要画成只有一个 tab 的切换器）

相位（paymentPhase）：select 选择中 ｜ paying 支付进行中
  - 进入 paying 后，tab 切换器隐藏，整个内容区被支付状态面板替换
  - 订阅 tab 里选中套餐后（selectedPlan 非空），tab 切换器也隐藏

## 1.3 充值 Tab（select 相位）

自上而下五块：

1. 充值账户卡
   - 「充值账户」标签 + 用户名
   - 「当前余额」+ 金额（绿色强调）

2. 金额输入
   - 快捷金额 chip 组（数量不固定，且会被 min/max 过滤掉一部分——画的时候留 4~8 个的弹性）
   - 自定义金额输入框，placeholder 按配置显示区间，共四种形态：
     「10 - 5000」/「≥ 10」/「≤ 5000」/「请输入金额」
   - 校验失败时下方出琥珀色错误文案

3. 支付方式选择
   - 6 种：支付宝 / 支付宝直连 / 微信 / 微信直连 / Stripe / Airwallex
   - 每项：图标（28px）+ 名称 + 手续费率标签（fee_rate > 0 时才出，形如「手续费 2.5%」）
   - 不可用的置灰且不可点
   - 选中态要明显

4. 费用明细卡（输入金额有效时才出现）
   - 支付金额
   - 手续费 (N%)        —— feeRate > 0 时才出
   - 实付                —— feeRate > 0 时才出，加粗强调色
   - 到账余额            —— 汇率倍数 ≠ 1 时才出
   - 汇率说明脚注         —— 汇率倍数 ≠ 1 时才出，形如「按 1 CNY = 0.14 USD 折算」

5. 提交按钮
   - 全宽，文案 =「创建订单 ¥328.00」（带金额，币种符号动态）
   - 提交中：spinner + 禁用

空态：没有任何可用支付方式时，整块换成一张「暂不可用」空态卡。

## 1.4 订阅 Tab（select 相位，未选套餐）

1. 套餐卡列表，每张卡：
   - 平台徽章（颜色跟随平台）
   - 套餐名 + 描述（最多 2 行截断）
   - 价格（大号加粗）+ 币种代码 + 原价划线 + 折扣百分比徽章（有原价时）
   - 有效期后缀（注意单位：天 / 周 / 月，不是都按天算）
   - 倍率 ×N
   - 高峰倍率（peak_rate_enabled 时）
   - 配额：日限额 / 周限额 / 月限额三项，各自独立可有可无；三项全无时显示「配额：不限」
   - 适用模型范围（有限定时）
   - 特性列表（features 数组，逐条带勾）
   - 按钮：「立即订阅」／已有同组订阅时变「立即续订」

2. 当前生效订阅区（有生效订阅时）
   - 每条：分组名 + 倍率 + 高峰倍率 + 配额 + 剩余天数

3. 帮助区（配置了帮助内容时）
   - 帮助图片（可点击放大到全屏预览）+ 帮助文字

## 1.5 订阅 Tab（已选套餐 = 确认页）

套餐列表被替换成确认卡：

1. 套餐确认卡：平台徽章 + 套餐名 + 价格 + 原价划线 + 描述 + 倍率 + 高峰倍率
   + 日/周/月限额（或「不限」）+ 有效期
2. 支付方式选择（同 1.3 第 3 块）
3. 费用明细卡（feeRate > 0 且价格 > 0 时才出）
4. 确认按钮（全宽）+ 取消按钮（次要样式，返回套餐列表）

续订弹窗：从别处触发时，弹窗里放套餐卡列表供选择。

## 1.6 支付进行中（paying 相位）—— 5 个状态

这是最容易漏的部分，5 个都要画：

  二维码等待     二维码图 + 实付金额 + 商户订单号 + 倒计时「剩余 04:32」
                 + 扫码提示 + 「保存二维码」按钮

  支付宝唤起     两个子态：
                 launching    「正在打开支付宝…」+ spinner
                 backgrounded 「请在支付宝中完成支付」+「重新打开支付宝」按钮
                 下方都有等待提示

  支付宝降级     唤起失败时的兜底：标题 + 说明 + 二维码 + 「长按保存后扫码」提示

  成功           成功图标 +「充值成功」/「订阅成功」（按订单类型区分文案）
                 + 明细（订单号 / 商户单号 / 金额 / 实付）+ 返回按钮

  已取消/已过期   两张独立状态卡，各有图标 + 标题 + 说明 + 返回按钮

## 1.7 响应式

- 移动端：卡片间距压到 16px；快捷金额 chip 换行；支付方式改单列；
  费用明细保持两栏对齐（左标签右数值）不要换行

## 2.1 定位

对外报价页。这一页有两种形态，是最容易漏的一点：

  独立形态   默认，未登录也能访问        自带顶部导航条，内容区 max-width 约 1280，
                                        不套 ConsoleShell
  内嵌形态   URL 带 ?embedded=1 且已登录  套完整 ConsoleShell

?embedded=1 但未登录时自动降级为独立形态。

独立形态的导航条需要单独设计：Logo + 站点名（都动态）+ 右侧「登录」按钮或
「返回控制台」按钮（按登录状态二选一）。

## 2.2 筛选栏

四组控件，横向排列：

1. 平台：chip 组，首项「全部」
2. 分组：chip 组，首项「全部」
3. 倍率：chip 组，首项「全部」
4. 模型搜索：文本输入框 + 清除按钮

chip 数量不定，需要考虑换行或横向滚动。

## 2.3 分组分区

每个分组一个 section，头部包含：

- 分组名（左侧有平台色粗边框条）
- 平台标识
- 倍率 ×N
- 用户专属倍率（有则显示，与通用倍率并列）
- 高峰时段：起止时间 + 高峰倍率
- 徽章：「专属」（is_exclusive）／「订阅制」（subscription_type === 'subscription'）
- 分组描述
- 高峰说明脚注
- 长上下文计费说明脚注

## 2.4 定价表 —— 本页的核心难点

双层表头，8 列：

```
┌──────┬─────────────────────────┬─────────────────────────┬──────┐
│      │      站内价格 /百万      │      官方价格 /百万      │      │
│ 模型 ├───────┬───────┬─────────┼───────┬───────┬─────────┤ 倍率 │
│      │ 输入  │ 输出  │  缓存   │ 输入  │ 输出  │  缓存   │      │
└──────┴───────┴───────┴─────────┴───────┴───────┴─────────┴──────┘
```

- 「模型」和「倍率」是 rowspan="2"
- 「站内价格」和「官方价格」各 colspan="3"
- 「官方价格」组用弱化色，与「站内价格」形成主次

单元格有 5 种变体，都要画出来：

1. 普通价格：$3.00
2. 分层定价：同一格里多行，每行前面带档位标签（如 ≤200K），其中一档可能带「边际」徽章
3. 时段定价：显示生效倍率 + 时段说明，hover 出 tooltip
4. 缓存写/读拆分：缓存列里分两个值，各带「写」「读」小标签
5. 按次/按图计价：整行价格区（3 列）合并成一格，显示「$0.04 / 张」或「$0.02 / 次」

## 2.5 响应式 —— 这一页的主要风险

8 列双层表头在 1024 内容区里必然放不下。请二选一并明确画出来：

方案 A：列优先级降级
  1280 隐藏「官方价格」整组（3 列），1024 再把缓存列并进 tooltip

方案 B：表格横向滚动
  「模型」列 sticky 吸左，其余横向滚动，滚动区两侧加渐变遮罩提示

我倾向方案 A，因为官方价格是参考信息不是决策信息，隐藏代价最小。
但你如果认为 B 更好，说明理由并画出来。

移动端：定价表改成卡片流，每个模型一张卡，站内价格突出，官方价格折叠。

## 3.1 定位

单栏卡片流，容器最大宽度约 950px，卡片间距 24px。侧栏高亮：个人资料。

这一页组件多但结构简单，主要工作量在于 8 张卡的层级和 4 个弹窗。

## 3.2 卡片清单（按顺序）

① 概览 Hero（渐变底，与其余卡片区分）
   - 头像 80px 圆角矩形（约 28px 圆角），无图时显示首字母
   - 用户名（大号）+ 角色徽章（管理员/用户）+ 状态徽章（正常/已禁用）
   - 邮箱
   - 第三方来源提示 chip（形如「头像来自 LinuxDo」「用户名来自 钉钉」，0~2 个）
   - 三个指标格：账户余额 ｜ 并发限制 ｜ 注册时间

② 基本信息（两列）
   - 左：头像卡 —— 预览 +「上传」（接受 image 类型）+「保存」+「删除」
     + 上传提示（自动压缩到 20KB）
   - 右：用户名编辑表单 —— 输入框 +「更新资料」按钮（提交中变「更新中…」）

③ 身份绑定
   5 个 provider，每行一条：
   邮箱 ｜ LinuxDo ｜ 钉钉 ｜ OIDC（名称动态，来自配置）｜ 微信（分公众号/开放平台
   两种，按配置显示其一或两者）

   每行：provider 图标 + 名称 + 状态（已绑定 / 未绑定）+ 操作按钮（绑定 / 解绑）

   邮箱行是特例，点击后展开内联表单：
   - 邮箱输入
   - 验证码输入 +「发送验证码」按钮（点击后进入倒计时 59s）
   - 当前密码输入
   - 提交按钮
   - 文案分两套：首次绑定 vs 更换邮箱（更换时密码框 placeholder 也不同）

④ 联系客服（配置了联系方式才出现）
   图标 +「联系客服」+ 联系方式文本。与其余卡片视觉区分（现有实现用了主色浅底）。

⑤ 修改密码
   当前密码 / 新密码 / 确认新密码 三个 password 输入 + 密码规则提示 + 提交按钮

⑥ 余额不足通知（功能开启时才出现）
   -「启用通知」开关
   - 阈值输入（number），placeholder 显示系统默认值，形如「系统默认 $5」
   - 附加通知邮箱区：
     · 顶部黄色提示文案
     · 已有邮箱列表，每条：邮箱 + 启用开关 + 状态（已验证 绿 / 待验证 黄）
       +「发送验证码」/「重发」+ 验证码输入 +「验证」+「移除」
     · 新增邮箱输入 + 添加按钮
     · 未验证的条目要能展开出验证码输入行，这是一个内联的两态

⑦ 两步验证 (TOTP) —— 三种态
   - 未开启：说明 +「启用」按钮
   - 已开启：「已启用」徽章 + 启用时间 +「关闭」按钮
   - 功能未开放：灰态说明

⑧ Passkey（功能开启时才出现）—— 四种态
   - 有凭据：列表，每条 = 名称 + 创建时间 + 最后使用时间 +「已同步」标记 + 重命名 + 删除
   - 空态：说明 +「添加 Passkey」
   - 浏览器不支持：灰态说明
   - 功能未开放：灰态说明

## 3.3 四个弹窗

TOTP 设置向导
  二维码 +「手动输入」可展开的密钥文本（等宽字体、可复制）+ 6 位验证码输入
  + 二选一的身份确认（邮箱验证码带发送冷却 ／ 当前密码，取决于后台配置）
  +「验证」按钮。请把两种身份确认方式都画出来。

TOTP 关闭确认
  警告文案（role="alertdialog"）+ 邮箱验证码（带发送冷却）+ 当前密码 +「确认关闭」

Passkey 添加
  名称输入 + 当前密码输入 +「继续」按钮
  （点击后浏览器会弹系统级 WebAuthn 提示，画一个等待态）

Passkey 删除确认
  role="alertdialog" +「确认删除 xxx？」+ 当前密码输入 + 确认按钮

顺手改一处：现有实现的 Passkey「重命名」用的是浏览器原生 window.prompt，很突兀。
请画成内联编辑或一个小弹窗。

## 4.1 定位

数据密集型监控页。控件最多的一页，工具栏一共 15 个交互元素，响应式降级是主要难点。

- 侧栏高亮：渠道状态
- 这一页承接的是渠道维度的指标。仪表盘只放用户侧摘要，两边不重复。

## 4.2 页头

- 标题「渠道状态」
- 副行：「已更新至 14:02」／ 刷新中时显示「更新中…」+ spinner
- 覆盖不完整警告（数据没铺满所选时间范围时）
- 冷启动进度卡（首次采集时）：标题 + 说明 + 进度条（role="progressbar"）+ 百分比
- 右侧刷新按钮（icon）

## 4.3 工具栏（横向可滚动）

从左到右 8 组：

1. 时间范围：4 个 chip —— 90 分钟 / 24 小时 / 7 天 / 30 天
2. 平台筛选：多选下拉，默认「全部平台」
3. 分组筛选：多选下拉，默认「全部分组」
4. 模型筛选：多选下拉，默认「全部模型」
5. 清除筛选按钮
6. 分组维度下拉，4 选：按平台 / 按平台+分组 / 按平台+模型 / 按平台+分组+模型
7. 趋势视图切换：脉冲 ／ 折线
8. 健康模式切换（仅在脉冲视图下出现），4 选：综合 / 成功率 / TTFT / 缓存

## 4.4 KPI 区

4 或 5 个指标格，数量由配置决定：

  成功率        副行「错误率 N%」        必出
  TTFT P50      副行 P90/P99            必出
  TPS           副行说明文字             可选（吞吐量开关关闭时隐藏）
  缓存命中率     副行说明文字             必出
  RPM           副行说明文字             可选（同上）

网格：显示吞吐量时 5 列，不显示时 4 列。两种都要画。
每格带健康状态色（正常 / 警告 / 异常 三档）。

## 4.5 主视图（二选一，都要画）

A. 脉冲矩阵
   - 左侧固定区：维度名 + 状态点，后接 4 个数值列（成功率 / TTFT / TPS* / 缓存率）
   - 右侧时间轴区：每行是该维度在各时间桶的健康色格子
   - 格子色阶就是健康度语义（这里允许用语义色，是本页唯一例外）
   - 无流量的桶用独立的空样式（不能和「健康度低」混淆）
   - 顶部：桶粒度徽章（如「5 分钟」）+「滚轮缩放 X 轴」提示 +「重置缩放」按钮
   - 格子 tooltip 含 7 项：健康分 / 成功率 / TTFT / TPS* / 缓存率 / 错误率 / RPM* / 总耗时
   - 空态

B. 折线图
   - 3 条线：错误率（红）/ 缓存率（绿）/ TTFT（蓝）
   - 双 Y 轴：左轴百分比，右轴毫秒
   - 图例在标题行右侧
   -「重置缩放」按钮
   - 加载态、空态

   上一轮评审提过「双 Y 轴不可判读」的问题。这里保留双轴是因为百分比和毫秒量纲差太远，
   但请把右轴的颜色与 TTFT 线绑定（轴标题和刻度用蓝色），让读者一眼知道哪条线读哪个轴。

## 4.6 下方 Tab（三选一）

模型 ／ 错误 ／ 用户

模型表
  平台·模型     主行模型名 +「已忽略」徽章（可选）
  成功率        主值 + 副行错误率
  TTFT P50      主值 + 副行 P90/P99
  TPS           可选列
  缓存率        单值
  RPM           可选列

错误表
  - 按错误分类分行，可展开
  - 展开后的详情行是管理员专属，用户端不画。用户端展开后只显示一句「暂无更多信息」

用户表
  排名          排名徽章（前三名有特殊样式）
  用户          用户名 +「当前用户」高亮标记（是自己时）
  成功率 / TTFT / TPS* / 缓存率 / RPM*    同模型表

三个 Tab 都要有：加载态、空态。

## 4.7 响应式 —— 这一页的主要风险

工具栏 15 个控件在 1024 内容区放不下。请明确定义降级顺序，建议：

```
1440    全部展开，单行
1280    三个多选筛选收成图标 + 计数徽章（如 [平台 2]）
1024    时间范围 chip 收成下拉；工具栏允许横向滚动，两端加渐变遮罩
移动端   工具栏收进一个「筛选」抽屉，页头只留时间范围下拉 + 刷新
```

表格列优先级（与 API 密钥页一致的思路）：

```
≥1440   全部列
1280    隐藏 RPM
1024    再隐藏 TPS（此时正好等于吞吐量关闭时的列集）
移动端   表格改卡片流
```

脉冲矩阵在 1024 下：左侧数值列砍到 2 个（成功率 + TTFT），时间轴区保持横向滚动。

## 后记（不要贴给 Claude Design）

### 需求是从源码盘出来的，不是照页面名猜的

对应的源文件：

| 页面 | 主文件 | 子组件 |
|---|---|---|
| 充值 / 订阅 | `views/user/PaymentView.vue`（1160 行） | `components/payment/` 12 个组件 + 6 个工具模块 |
| 模型广场 | `views/ModelPlazaView.vue`（48 行，只做形态分发） | `components/modelPlaza/` 5 个组件，1163 行 |
| 个人资料 | `views/user/ProfileView.vue`（115 行） | `components/user/profile/` 11 个组件，2976 行 |
| 渠道状态 | `views/user/ChannelStatusV2View.vue`（944 行） | `features/channel-monitor-v2/` 6 个 + `components/user/monitor/` 7 个 |

### 三个只看页面名一定会漏的点

**模型广场是双形态页面。** `ModelPlazaView.vue` 里 `isEmbedded = route.query.embedded === '1' && authStore.isAuthenticated`——默认是未登录也能访问的独立形态，自带导航条；带 `?embedded=1` 且已登录才套 console shell，未登录时自动降级。这是两张画板，不是一张。

**充值页有两个正交维度。** Tab × 相位，`paying` 相位会把内容区连同 tab 切换器一起替换。光支付进行中就有 5 个状态。只画一个"支付中"是不够的。

**渠道状态工具栏有 15 个控件。** 在 1024 内容区必然放不下，所以我直接把降级顺序写成建议方案而不是让它自己发挥——上一轮的教训是响应式不给具体方案它就会算错。

### 两处我主动做了取舍

**模型广场双层表头给了推荐方案。** 方案 A（隐藏"官方价格"整组）比方案 B（横向滚动）代价小，因为官方价格是参考信息不是决策信息。留了口子让它反驳。

**双 Y 轴决定保留。** 第一轮我把它列为 P2 问题，但百分比和毫秒量纲差太远，强行单轴更难读。改成要求把右轴颜色与 TTFT 线绑定来解决可判读性——这是对我早先判断的修正。

### 顺带带进去的两件事

- `--color-danger` 亮色 `#dc2626` → `#d92020`（4.47:1 → 4.65:1），放在全局约束里让它顺手更新 Design System 画板
- Passkey 重命名现在用浏览器原生 `window.prompt`，标了"改成内联编辑"

### 与工程侧的衔接

这份需求不阻塞工程侧的 B1（抽 `theme.css` 变量、自托管 Google Fonts、修 `console-shell.js` 余额按钮的 `aria-haspopup` 不匹配）。两边可以并行。
