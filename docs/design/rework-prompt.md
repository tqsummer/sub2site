## 1.1 文本对比度不达标

实测两个色值低于 WCAG AA 标准（正文需 ≥4.5:1）：

  亮色 --color-text-3  #8c90a3 on #f5f6fa = 2.93:1  ✗
  暗色 --color-text-3  #6f7386 on #131520 = 3.87:1  ✗

请替换为（已验算，保留原蓝灰色调并留有余量）：

  亮色 --color-text-3: #64687a   → 5.11:1  ✓
  暗色 --color-text-3: #868a9b   → 5.30:1  ✓

其余色值经复核全部达标，不要改动：
  亮 text-1 #171922 = 16.22:1 · 亮 text-2 #595d6c = 6.06:1 · 亮 accent-text #2563eb = 4.79:1
  暗 text-1 #e9e9ed = 15.01:1 · 暗 text-2 #9ea2b5 = 7.17:1 · 暗 accent-text #7aa2f7 = 7.21:1

注意：亮色 accent-text 是 4.79:1，刚过线。它只用于链接和强调数字，不要用于小于 14px 的文本。

## 1.2 开关（Toggle）键盘不可操作

现状：API Keys 画板里的开关是 `<label>` + `<span>` + onClick，没有真实表单控件，键盘完全无法操作。

改为原生控件 + ARIA：
  <button type="button" role="switch" aria-checked="true|false" aria-labelledby="xxx-label">
  或 <input type="checkbox" role="switch"> + 视觉层
必须支持：Tab 聚焦、Space/Enter 切换、:focus-visible 显示焦点环。

涉及位置：创建/编辑密钥弹窗里的 4 个开关（自定义 Key、IP 限制、速率限制、有效期）。

## 1.3 模态框缺少语义与焦点管理

现状：弹窗只是普通 div，没有任何 ARIA。

每个模态框必须包含：
  role="dialog" aria-modal="true"
  aria-labelledby 指向标题元素的 id
  aria-describedby 指向描述文本（如有）
并在设计稿中标注以下行为规范：
  · 打开时焦点移入弹窗（首个可交互元素或关闭按钮）
  · Tab 循环限制在弹窗内（焦点陷阱）
  · Escape 关闭
  · 关闭后焦点返回触发元素

## 1.4 焦点态与动效偏好

  · 所有可交互元素补 :focus-visible 焦点环：2px solid var(--color-accent)，offset 2px
  · 补 @media (prefers-reduced-motion: reduce)：关闭所有 transition 与 animation
  · 当前 8 个画板中零个 aria-* 属性，请系统性补齐（表格排序按钮 aria-sort、进度条 role="progressbar" + aria-valuenow、Tab 组 role="tablist"/"tab"/"tabpanel"、Toast role="status"）

## 4.1 平台识别色（当前完全缺失）

五个 AI 平台的识别色在 Dashboard、API Keys、Subscriptions 三个画板里各自硬编码，设计系统里一个字没提。请正式定义为 token：

  --platform-claude:       #d97757
  --platform-openai:       #10a37f
  --platform-gemini:       #4285f4
  --platform-grok:         待定（见下）
  --platform-antigravity:  待定（当前完全没有色值）

两个问题需要你解决：
  · Grok 现在用的 #8c90a3 与 --color-text-3 是同一个值，平台识别色和弱化文本色角色耦合。请为 Grok 另选一个色值
  · Antigravity 在落地页厂商墙和 Console 厂商表里出现，但 Dashboard 平台拆分、API Keys 分组、Subscriptions 订阅卡三处全都缺席。请补上，并给它一个识别色

同时：Dashboard 平台拆分卡的网格当前写死 repeat(5)，补上 Antigravity 后会挤，改为自适应。

## 4.2 图表分类色板（当前挪用语义色）

Token 趋势图的 5 条线里有 2 条用了 warning 和 success 色，这违背了"语义色只表达状态"的原则。请定义一组独立的图表分类色（建议 6-8 色，在亮暗两个主题下都可辨识，且对色觉障碍友好）。

## 4.3 暗色 accent 色阶缺失（Bug）

aiproxy-theme.css 的亮色定义了 --color-accent-100 到 900 九档，但 [data-theme="dark"] 块里没有重新定义，导致暗色下继承亮色色阶。请补齐暗色的九档。

## 4.4 间距规范化

设计系统页声明的间距阶是 [4,8,12,16,20,24,32,48]，但实际画板里大量使用了 6、10、14、18、22px 这些不在阶上的值。请统一到声明的阶梯，或者扩充阶梯并说明每一档的用途。

五、补危险操作确认稿（当前一个都没有）
═══════════════════════════════════════

API 密钥页有四类破坏性操作，目前全部没有二次确认设计：

  1. 删除密钥
  2. 停用密钥
  3. 重置配额用量
  4. 重置速率限制窗口用量   ← 这一项容易漏，它和第 3 项是两个独立操作

每一个都需要确认弹窗，且要区分严重度：
  · 删除 = 不可逆，用 danger 样式，确认按钮需要明确文案（不是"确定"，而是"删除密钥"）
  · 停用 / 重置 = 可逆，用普通样式

另外补两个已有但没画的浮层：
  · 客户端导入选择弹窗（"导入"按钮当前是死按钮）
  · 新建密钥成功后的一次性完整密钥展示弹窗（这个组件躺在 Components 画板里，没有接进流程）

## 6.1 需要标注为动态的内容

  · 所有出现 "AIProxy" 的界面文本（侧栏品牌名、落地页导航/主视觉/页脚、版权行、API Keys 空状态文案）

  · API 域名 api.aiproxy.example

请在设计稿中把这些标注为变量占位（如 {{siteName}}），而不是固定文字。

## 6.2 Logo 插槽（重要）

当前 Logo 是纯 CSS 画的正方形色块 + 旋转菱形，在 5 处独立复制、尺寸各异（28/24/20/18px），且内部硬编码了白色。

问题：后端允许上传任意图片，横版长图会撑坏当前布局。

请设计一个 Logo 插槽规范：
  · 支持正方形（1:1）和横版（最宽 4:1）两种比例
  · 定义各位置的最大高度与容器行为
  · 定义 Logo 缺失时的降级（首字母方块或纯文字）
  · 补 favicon 规格（当前完全没有）

## 6.3 不要改的部分

代码示例里的 AIPROXY_API_KEY 环境变量名、sk-ap- 密钥前缀、provider 标识符 aiproxy —— 这些受 CLI/SDK/后端校验契约约束，保持现状，我会单独处理。

## 7.1 时间格式（当前混用四种）

画板里同时出现了完整日期、14:02:31、昨天 22:10、08-30 09:12 四种格式，没有规则。请定义：
  · 相对时间的使用范围（多久以内用"x 分钟前/昨天"）
  · 绝对时间的格式与是否省略年份
  · 时区标注方式（产品有高峰时段计费，时区必须明确）

## 7.2 币种分层（不要机械统一）

不同场景币种不同，不能全站统一成一种：
  · 账户余额与用量统计 —— 美元
  · 订阅套餐价格 —— 人民币
  · 支付金额 —— 跟随所选支付渠道，是动态的
请在设计系统里明确三者的区分与展示规则。

## 7.3 密钥配额字段

当前示例数据把配额画成了百分比（0.31 / 0.97），但真实数据模型是「已用金额 / 上限金额」两个字段。请改为展示实际金额，如「$31.20 / $100.00」+ 进度条，而不是只有一个百分比。
